# SkiZones v0.42.5 — Save/Load Reliability Emergency Hotfix

**Status:** Draft until the complete GitHub Actions, Android update, and real Samsung tests pass.

## Player-facing fixes
- The active resort can be saved on **every valid game day**. The existence of a later game-day checkpoint or backup no longer blocks the Save button or periodic autosave.
- An intentional save of an earlier game day becomes the active checkpoint and loads at the exact saved game day and minute. A later backup can no longer silently override the active save after a legitimate rewind.
- Before any newer main/backup checkpoint is displaced, its original bytes are archived in `user://save-recovery/`, with SHA-256 verification. If an older main file is advanced past a newer backup, the newer backup is also preserved before normal rotation.
- Normal writes still stage to a temporary file, verify the payload checksum, perform a fresh semantic restore, and only then replace the active save. Legacy transient guest routes may be normalized when safe, while invalid permanent construction data remains rejected.
- The career/index files and package identity remain unchanged; the Android version is `0.42.5` / `versionCode 62`, designed as an in-place update of `0.42.4` / `versionCode 61`.
